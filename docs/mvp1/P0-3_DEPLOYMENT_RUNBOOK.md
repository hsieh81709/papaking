2. 由已授權帳號唯讀匯出**目前正式**GAS全檔及manifest；記錄Script ID、所有部署ID、版本號、版本說明、執行身分、存取設定、實際Webhook URL、觸發器、頻道識別（非secret）、來源分支／Commit與檔案雜湊。實際部署版本對應可能不是Git最新版本，不可只記HEAD。
3. 憑證與Script Properties值由持有人備份至有存取稽核的加密儲存，不進Git或一般報告。另記非敏感設定名稱／是否配置、配額策略及切換前執行紀錄。保留quota鹽與計數，避免回復時意外重設額度；不將正式個人ID／位置複製到fixtures。
4. 本階段只涉及程式發布，**不改Sheets schema或座標**。需要資料備份時，由使用者另外核准建立只讀快照，核對分頁、欄位、筆數、ID與原9筆正式座標雜湊；不可順便建發布清單、同步B4-5或匯入合成核准。
5. 保存舊不可變GAS版本與可回復的部署，不刪除原部署／憑證；Git候選標籤與SHA須對照實際GAS版本。備份無法讀回或舊Webhook／部署版本不明時停止切換。

## B. 隔離驗收（授權後才執行）

所需最小資源：獨立Google測試帳號或受控測試專案的編輯權、隔離GAS Script ID及版本、合成工作簿的讀取權；獨立LINE測試頻道的Messaging API授權及Webhook設定權；後續獨立ingress的測試secret與日誌權。Google OAuth由持有人在安全介面完成，不在聊天傳Token。正式GAS原始碼／部署清冊僅需對應唯讀權（例如Apps Script projects.readonly與deployments.readonly依API需求），正式資料盤點僅試算表唯讀。建立測試專案／部署的權限只適用隔離資源，另確認帳號／Script ID，不能以 `isolated` 字串代替技術隔離。

1. 建立獨立頻道與GAS／ingress，核對不是正式ID。工作簿只放合成資料，不複製使用者私有位置或正式核准內容。
2. 將候選的四個serving JS及manifest以固定來源匯入，從GAS再次唯讀匯出，按檔名及內容雜湊比對；若工具正規化換行，保留原始hash並另記明確canonical規則，不忽略實質差異。記錄版本號、deployment ID與時間。服務專案不納入批次維護檔／trigger。
3. 在測試環境配置必要屬性，核對PARK_SHEET_ID。manifest目前推導OAuth scopes，不能宣稱最小權限已成立；建立服務專案後檢查實際提示權限，評估將Spreadsheet呼叫限定唯讀scope是否相容。Maps／外部HTTP與原停車依賴需逐項實測；未完成前不能自行替正式manifest加scope。
4. 合成表包括臺北有效公園、新北未核准／核准／撤銷／指紋變更公園、公廁UNKNOWN、無效座標、空結果及格式錯誤。核准只存在隔離工作簿。確保無表或不符指紋時新北結果為0。
5. 使用 `LINE_MESSAGES.json` 去除notice包裝後，逐批呼叫官方 `/message/validate/reply`，保存UTC、候選SHA、訊息hash、官方狀態及去識別錯誤回執。Access Token不入log；validate API不寄送訊息。
6. 在測試LINE頻道走真實簽章入口：三分類→位置→Flex／文字→Google Maps；不同DM／group／room、分類切換、599／600秒、新舊事件交錯、重送及並行都需有事件ID去識別回執。驗證未簽章、origin直打、nonce重放零查詢。不得以本地Cache模型代替真實服務驗收。
7. 停車以固定公開點驗證1km路邊／路外、TDX／NTPC來源、TWD97、排序／行車時間與Maps失敗備援、導航、Static Fallback及月／群限制。需真實外部資料者限制次數／成本；429／401、故障與並行額度優先在隔離stub fault adapter測，不靠耗盡正式金鑰或停用正式服務。記錄各項 `passed`／`not_exercised`；沒有結果不等於Flex卡已驗收。
8. `testPapaKingLiveParkingV2` 只有操作者核對隔離ID、配置測試屬性後才可執行；會呼叫外部來源，不能當作無成本唯讀腳本。其填入Commit／version仍須另驗匯出來源，不自行證明版本一致。不執行批次park_geocoding。
9. 實機查閱Flex／文字、Maps代表點與實際入口用語；導航可開啟不等於位置品質已核准。公廁UNKNOWN不可呈現「無」或24小時。未核准公廁可展示未開放提示，不允許為展示而降低發布門檻。

## C. 正式切換（必須使用者明確核准）

1. 交付A／B的完成證據、所有未通過項、備份位置、精確候選SHA、實際GAS版本及回復目標，取得本次切換範圍、資源ID與窗口的明確核准。
2. 確認正式安全ingress與origin驗證已備妥，測試／正式secret分離。正式頻道LINE Webhook應指向**驗證簽章的入口**，不直接指向未保護的GAS。新服務獨立於sponsor-worker。
3. 建立不可變GAS版本、更新指定deployment並記錄版本對照；從live版本再次匯出／驗hash，必要設定依核准清單逐項變更，不打開批次trigger、不改座標表。
4. 在LINE Developers Console保存舊Webhook URL與選項，切換至核准入口，驗證連線與簽章完整流程。啟用redelivery需在可靠去重／狀態完成後另記設定；Verify按鈕成功只證明連線回應，不證明訊息功能或簽章防護完整。
5. 由指定測試帳號以公開位置做每類一次smoke；停車正常且來源與導航正確、臺北公園正常、新北／公廁只顯示已核准資料或明確未開放提示。保持已核准正式9筆座標不變。不強制為公廁建立資料核准。
6. 若回覆重複、停車功能回歸、未核准導航或安全檢查失敗，立即啟動D，不因本地測試綠燈而繼續放量。

## D. 監控與回復

監控最低項：入口簽章／origin拒絕率、唯一事件及去重命中、處理延遲與租約逾時、跨分類錯誤／重複停車、LINE 400／401／429／5xx及傳送不確定、TDX輪替與配額、Maps錯誤與直線備援、NTPC讀取／Static Fallback率、Sheets格式錯誤／發布拒絕／零核准、Cache逐出／分類逾時、每日外部呼叫與額度計數一致性。設定基準與告警閾值須由隔離／既有流量證據決定，不虛構本輪可量測的SLO。

日誌只留事件ID的受控hash、候選版本、類別、狀態與耗時；不記Token、secret、完整body、原始userId或使用者座標。保存限制、責任人與告警管道在切換前確認；本輪不發送任何外部通知。

回復順序：

1. 操作者依已核准的回復門檻停止新候選處理；暫停受控queue的取件，不刪去重帳本，保留reply-attempted／uncertain紀錄，避免回復後再發一次。
2. 恢復**切換前已備份的實際**GAS deployment版本及必要設定，再將LINE恢復原已核准Webhook URL／選項；若舊URL本身不安全或不相容，使用預先批准的維護入口，而不是直接開回未驗證GAS。
3. 核對簽章／originsecret與版本成套相容，憑證只在疑似洩漏且有替換計畫時輪替；不能盲目還原舊密鑰讓已撤銷憑證恢復有效。
4. 分類Cache版本採新namespace或明確失效策略，不全域清除停車快取／重設月額度。需要使用者重新選分類時給清楚提示。重跑公開點停車、臺北公園及無核准拒絕導航smoke，確認沒有重送query／reply。
5. 不回寫或還原任何Sheets座標；本次程式切換本來不應改資料。若意外發生寫入，停止服務、保留修改紀錄，提出獨立資料復原計畫等待授權，不執行B4-5。
6. 保存事件時間線、失敗版本、已處理帳本與檔案hash，記錄撤回結果。只有回復驗收及重新核准後才能再切換。

目前正式舊版本／URL未知，故D尚未演練，**不可直接照未知目標回復**。本輪Git新增驗證文件／工具可用 `git revert <P0-3交付Commit>` 另建撤回Commit；候選855f5f2的執行程式未變，Git revert不等同GAS回復。
