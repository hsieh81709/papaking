# MVP 1.0 最小整合方案、後續任務與上線阻擋

規劃日期：2026-10-21。這是待核准計畫；本輪沒有實作、安裝觸發器、同步或部署。程式與資料依據見[SYSTEM_REVIEW.md](SYSTEM_REVIEW.md)。工作量為一名熟悉GAS工程師的估算，不含等待人工審核、帳號授權或正式變更窗口。

## 產品與架構決策

保留單一既有Webhook。三個主要入口固定為「停車查詢」「附近公園」「附近公廁」，皆選類別→分享位置。沒有分類的直接位置維持舊停車行為；選單不含遊具篩選。舊遊具文字需明確回覆本版僅提供附近公園，或在核准的相容方案下映射全部，不繼續暗中啟用篩選。

公園沿用雙北、3km、最多5筆、直線距離排序及代表點walking導航。公廁第一版建議同樣3km／最多5筆，僅納入新北核准子集；這是待確認的產品預設，不能以同範圍假設資料已驗收。停車繼續1km及原行車時間策略，不套公園的top5或walking規則。

新北公園不等635筆全部完成，9筆原正式座標保持不動；逐筆確認可發布範圍。公廁也不必一次核准3976筆，但啟用前至少有可重現的核准測試子集及覆蓋揭露。若完全無核准資料，公廁入口只能回覆「資料尚待驗收，暫無可導航結果」，不能宣稱附近沒有公廁，也不能宣稱三類導航上線驗收完成。

## 共用函式如何對應既有程式

以下為後續API契約建議，不是本輪新函式：

| 概念 | 優先使用的現有能力 | 必須補齊的契約 |
|---|---|---|
| `getFacilityData(kind)` | `parkRowsAsObjects_`與既有`PARK_SHEET_ID`工作簿 | park/toilet各自表頭映射，嚴格ID唯一性、已核准來源、縣市與狀態，缺表回分類錯誤；不讀候選 |
| `searchNearbyFacilities()` | `parkSearch_`的半徑／排序／topN，距離用`parkDistanceKm_` | 輸入先驗格式與數值範圍；統一回傳`kind,id,name,city,district,address,lat,lon,km,positionType,sourceVersion`；明細不用join倍增主表 |
| `calculateDistance()` | 保留現有兩個距離函式；新共用設施用公園版 | 不順手重構停車數學或半徑；3km容差／同距離排序沿用既有測試 |
| `buildFacilityFlex()` | 公園`buildParkFlexReply_`既有卡片結構＋`papaKingFlexTheme_` | park/toilet共用資料shape；公廁加樓層／限制／開放時間未知提示；不顯示遊具、不把未知寫沒有 |
| `buildNavigationUrl()` | `parkNavigationUrl_`模式＋`papaKingMapUrl_` | 種類明確，walking為公園／公廁；未核實入口只寫代表位置。停車`navUrl`driving不變 |

發版gate不以ID單獨放行：記錄`facilityKind、ID、正式座標值或hash、來源快照hash、人工核准人／日期、證據URL、座標代表類型、發布範圍／版本`。正式點位一旦改值，舊核准應失效；缺核准或未知狀態均不產生導航。先在唯讀發布manifest／fixture驗證這個契約，不改Sheets；未來若要寫正式表需另提執行計畫與授權。

公廁原表的待驗收／待確認狀態不就地改寫。可先在人工核准後產生獨立唯讀發布快照，明載原始狀態、核准座標與發布決定，再由adapter同時驗manifest與快照版本；未列入明確發布範圍仍排除。這是待開發契約，不是本輪已生成可發布公廁資料。

臺北既有公園以經確認的目前正式基準快照維持相容，不要求一次重審全部813；新北公園與新加入公廁使用明確發布範圍。歷史`修正座標驗收=已確認`有助核對，但本次ODS來源一致性驗收不代替發布決定。

## 分類狀態與錯誤處理

- 共用對話＋使用者隔離key，保存category與到期，不同類別不得各留一份互相覆蓋不明的狀態。選任一新類別取代舊類別，停車指令及回選單都清除舊公園／公廁意圖。
- 位置訊息只消費一次當前類別；完成或取消後恢復舊停車預設。無效位置明確提示重分享；是否保留重試意圖需用測試固定，不能錯誤切成停車。
- Cache目前不是可靠的永久會話；TTL到期／提前逐出會恢復停車。MVP至少在提示說明一次性與有效時間，明確傳送分類逾時訊息需要可判別的狀態記錄，不能聲稱現有Cache能辨識已過期與從未選擇。
- 查詢／Sheets錯誤回覆「公園／公廁資料暫時無法讀取，請稍後重試」，不靜默轉查停車；空核准清單與附近沒有符合條件結果分開說明。
- 群組與room需有userId才能保存設施意圖；缺少身分時請到一對一，不以groupId作使用者。停車既有群組額度語意保留；是否讓公園／公廁共用月額度需明文決策，目前公園會跳過`consumeQuota`。
- LINE事件重送、同使用者同時兩則位置／Cache get-remove非原子需有測試與可預測處置；不因新增類別改動原有停車key或額度上限。

## 未來正式操作前須另提的計畫

1. 明列目標script／deployment／Sheets、來源Commit及發布資料manifest，列出會改動與不改動資源；正式發版不自動帶入B3／B4-3觸發器。
2. 保存現行GAS全檔／版本與設定清單、LINE Webhook URL設定與必要資料快照；秘密以受控方式留存，不印出或提交。若任務只改應用程式，不順帶做資料同步。
3. 先隔離專案與測試資料演練，再依人工核准的變更窗口與清單執行；配額、導航可信度、簽章入口與群組行為列風險。
4. 指定失敗判準、切回舊部署／設定及資料manifest的方式；若真的需要正式Sheets寫入，另列逐ID差異、寫前備份與衝突回復方式，取得當次明確核准。
