# 新北市公園：副本同步驗證計畫（尚未執行）

此計畫以 dc768dd 的 B4-5 為基礎；本次只準備工具與計畫，沒有建立 Google 副本或寫入試算表。

| 關卡 | 執行方式 | 驗收證據 |
|---|---|---|
| 取得四表 | 一個完整 XLSX，保留原始檔，記錄來源雜湊 | 四表 inventory、列數、欄位、日期／公式狀態 |
| 母體與品質 | 檢查實際新北 635 筆、候選 ID 集合、空缺／重複、地址及行政區 | quality-report、逐筆 CSV；歷史計數只作比較，不覆寫事實 |
| 人工／公開來源 | 自主調查高風險記錄，保留官方來源及入口證據；未解決仍待審 | 待審名單與公開資料證據表，不以 A 級自動核准 |
| 隔離副本 | 取得 Google 授權後建立獨立副本，核對與正式表不同的 spreadsheet ID | 副本 ID、建立時間、讀回四表內容及雜湊比對 |
| 副本預檢 | 僅接受明確核准 ID、座標來源、人工已確認；保護全部既有非空正式座標 | 精確 before／after diff；九筆是歷史已知值，實際須重讀確認 |
| 副本備份與演練 | B4-5 寫入前備份與日誌；驗證 idempotence、逐點故障回復及中斷回復 | 副本備份／journal、實際 API 讀回；不以 Node mock 取代 |
| 搜尋回歸 | 三公里／五筆／排序／設施／共融／文字備援／Webhook 分流／停車 Static Fallback | 離線結果 + 副本讀取後的實際 GAS 測試，區分執行平台 |
| 正式同步 | 本任務不執行；須另外取得對真實逐筆差異的明確確認 | 單獨的使用者授權；副本成功不構成正式寫入授權 |

`park-verify-export.mjs` 取得真實檔案後會產生帶來源雜湊的 `copy-sync-plan.json`；在實際 Google API 副本驗證完成前，`readyForCopyExecution` 不會被離線測試設為 true，`productionWritesAuthorized` 固定為 false。

SpreadsheetLock 不是跨多個 Google 專案／人工編輯的資料庫交易。副本演練時也須確保沒有其他寫入者，保留備份／日誌，不自動修正或發布未審核座標。
