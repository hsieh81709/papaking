## 2. PK-04：選單取消與對話隔離

- 在 `doPost` 的選單分支消耗並清除**當前使用者／當前對話**的公園intent，再回選單。沒有公園模組時保留停車單檔模式。
- 「重新選擇」按鈕原本送出「選單」，現在代表取消舊條件。選單的「停車／分享位置」會走預設停車；重新點公園條件則保存新的intent。
- 沒有擴充「取消」「停車」為新的文字指令；取消此公園條件的支援操作是回選單。
- 新測試涵蓋user／group／room、同人不同對話、不同群組成員、選單別名、重新選擇、600秒TTL與一次性消耗。TTL以可控時計模擬CacheService契約，不宣稱驗證真實GAS快取服務。

來源：[webhook-routing.test.mjs](../../test/parks/webhook-routing.test.mjs)。

## 3. PK-05：同一資料快照的文字備援

- 公園查詢一次產生Flex與可選文字備援；`formatParkReply_`使用同一批結果，不重查Sheets或停車API。無結果也只查一次。
- `buildParkFlexReply_`保留原本三參數用法；內部可用第四參數接收文字。`replyLine`新增可選第三參數 `fallbackText`；它不會進入Flex JSON。
- 只有400拒收rich message時才嘗試一次文字備援；停車原有文字＋Flex仍優先使用已存在文字，文字統一遵守5000字元限制。
- 200不重送；429／500／transport exception不自動重送不確定的請求。純文字拒收、沒有文字可備援、第二次備援失敗均不迴圈重試。

新案例涵蓋上述狀態、無結果／無效座標、回覆token一致、沒有內部欄位外洩，以及沒有多餘資料查詢。來源：[line-fallback.test.mjs](../../test/parks/line-fallback.test.mjs)。

## 4. PK-06：非空斷言與可追溯回執

`testPapaKingLiveParkingV2()`仍只組出停車結果並檢查，不發LINE訊息；未在本輪連接任何GAS專案執行。

- 設定不完整、非隔離聲明、無script ID、非法座標或未知預期，會在查資料前失敗。
- `cards`：至少一張有內容的藍色停車bubble，空carousel、錯色、空body與上游錯誤都失敗。
- `static-fallback`：必須實際觀察到Static資訊卡；沒有命中不得以INFO代替通過。Static卡不能有導航footer。
- `empty`：必須無Flex，且同時具明確的路邊／停車場無結果文字；任意純文字或錯誤不是空結果成功。回執為 `PASS_EMPTY_RESULT`，卡片／Static斷言為 `not_exercised`。
- 成功回傳／記錄JSON回執，包含時間、script ID、填入的commit／GAS版本、公開fixture標籤、觀察數量、各實際斷言與未命中原因。回執不記錄原始測試座標。
- `sourceMetadataIndependentlyVerified=false`，以及LINE schema、LINE投遞、Sheets寫入的驗證旗標固定false。函式不能自行證明呼叫者填入的commit／版本真實，也不能以 `isolated` 字串當作環境隔離的安全證明。

Script Properties完整契約見 [gas/README.md](../../gas/README.md)。來源：[parking-diagnostic.test.mjs](../../test/parks/parking-diagnostic.test.mjs)。

**線上未完成部分**：仍須由已授權的隔離GAS／LINE測試資源、核對過的來源／版本與公開測試點取得真實服務回執，才能完成PK-06的線上驗收子項。未要求聊天提供Token，也沒有把新離線測試宣稱為線上成功。
