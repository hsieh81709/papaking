### PK-01：取得四表或唯讀連線

**問題／證據**：API metadata GET 回覆 Google 403 unregistered callers；clasp 未登入、ADC 為空設定，無完整四表檔案，且只有 Script ID 不等於 Spreadsheet ID。

**交付與驗收**：

- 優先讓使用者只下載／附加一次含公園資料、候選、設施、品質檢核四頁的 XLSX；既有 HTML 助手不需修改 GAS。
- 或以已授權帳號／受控服務身分、Viewer ACL、`spreadsheets.readonly` 成功 get＋batchGet 四頁；已知 ID 時不要求整個 Drive。
- 保留來源雜湊／欄位／列數、公式與日期限制；釐清歷史 ID 是否就是實際目標。不在聊天或 Git 保存 Token，單純新增 API Key 不算私有 Sheet 授權成功。

### PK-02：真實635筆稽核與來源完整性

**問題／證據**：歷史 635／634 等合計不能指出真實失敗 ID，原始建立候選的 GAS 程式仍缺漏。`park_geocoding_gas.js` 目前是新稽核器。

**交付與驗收**：

- 核對實際母體與 ID 集合，逐筆 A/B/C、原因、地址／行政區、同座標群組及正式／候選距離差；若筆數有異先解釋，不湊成635。
- 只有完整母體中確實僅一筆無效才宣稱唯一失敗 ID；不能引用合成 NP-635。以官方資料／管理單位／GIS查核高風險候選，標明支持身分、園區或入口；存來源與時間，未解決仍待審。
- 找回原始候選建立器並查覆寫／續跑／已核准保護；找不到時將該路徑列為未驗收。真實品質稽核可先做，不因缺原始模組而延後全部分析。

### PK-03：副本同步
